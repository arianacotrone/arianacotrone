## Sobre mí

Mi base de Ingeniería Industrial le suma a la ciencia de datos una mirada de proceso: no me quedo en el modelo, pienso en cómo ese análisis se integra al flujo de trabajo real de quien lo va a usar. 

Antes de sacar una conclusión, reviso de dónde salió el dato, qué tan confiable es la fuente y qué tan lejos me
deja llevar la evidencia disponible — no más.

Construyo cada proyecto de este perfil con datos públicos, pipeline propio y limitaciones documentadas explícitamente, no ocultas.

## Cómo trabajo

1. **Empiezo por la pregunta de negocio, no por el dataset.** Un análisis vale por la decisión que permite tomar, no por la complejidad del modelo detrás.
2. **Desconfío del dato hasta verificarlo.** Reviso consistencia, supuestos y documentación antes de construir cualquier conclusión sobre una fuente.
3. **Documento lo que el dato no permite afirmar,** tanto como lo que sí. Una limitación explícita vale más que una conclusión demasiado prolija.

## Proyectos destacados

**[`cortes-enre`](https://github.com/arianacotrone/cortes-enre)** — Pipeline propio de recolección de datos (scraping automatizado cada ciertas horas vía GitHub Actions) sobre cortes de energía eléctrica en el AMBA, más un análisis de más de 160.000 lecturas: reconstrucción de eventos a partir de datos crudos, comparación Edesur/Edenor y detección de una limitación real en la frecuencia de muestreo del propio pipeline.

**[`SistDeRec`](https://github.com/arianacotrone/SistDeRec)** — Sistema de recomendación de dos etapas (generación de candidatos + reranking con CatBoost) desarrollado para una competencia de ciencia de datos. Arquitectura pensada para el mismo tipo de problema que un sistema de scoring o de predicción de abandono de clientes en un contexto de negocio.

**[`infovis`](https://github.com/arianacotrone/infovis)** — Panel interactivo de storytelling con datos, con integración de múltiples herramientas de visualización (Flourish, Tableau Public, Datawrapper) sobre un mismo conjunto de datos.
